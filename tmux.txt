Mini-guide tmux pour Grid5000

1. Lancer tmux
tmux
Crée une nouvelle session et te place dedans.

2. Détacher la session
Ctrl + b puis d
Détache la session sans la fermer ; ton travail continue en arrière-plan.

3. Lister les sessions
tmux ls
Montre toutes les sessions tmux actives.

4. Revenir dans une session
tmux attach
ou si plusieurs sessions :
tmux attach -t <nom_session>

5. Renommer une session
Ctrl + b puis :
rename-session <nouveau_nom>

6. Créer une nouvelle fenêtre
Ctrl + b puis c
Pour lancer plusieurs programmes dans la même session.

7. Basculer entre les fenêtres
Ctrl + b puis n   # prochaine fenêtre
Ctrl + b puis p   # fenêtre précédente

8. Diviser la fenêtre en panneaux
Ctrl + b puis %   # diviser verticalement
Ctrl + b puis "   # diviser horizontalement

9. Naviguer entre les panneaux
Ctrl + b puis flèche directionnelle

10. Fermer un panneau ou une fenêtre
Tape exit ou Ctrl + d dans le panneau/fenêtre.

11. Copier-coller dans tmux
Entrer en mode copie :
Ctrl + b puis [
Déplacer le curseur et sélectionner le texte (espace pour commencer, déplacer, puis entrer pour copier)
Coller :
Ctrl + b puis ]

Astuces pour Grid5000
- Toujours lancer tmux avant oarsub -I pour éviter de perdre la session interactive si la connexion SSH tombe.
- Tu peux lancer plusieurs jobs dans différentes fenêtres ou panneaux de la même session tmux.
- Pour les GPUs sur Sirius : utilise tmux pour gérer ton session interactive OAR, car la réservation bloque tout le nœud.

Fin du guide.



=== Guide d'accès au Group Storage 'sto-cookyst' sur Grid5000 ===

---

## 1️⃣ Cas 1 : Sur Lille (même site que le storage)

* Storage sur : `storage1.lille.grid5000.fr`
* Chemin d'accès : `/srv/storage/cookyst@storage1.lille.grid5000.fr`
* Accessible directement depuis frontends ou nœuds réservés.

### Commandes utiles :

```bash
# Voir les fichiers
ls /srv/storage/cookyst@storage1.lille.grid5000.fr

# Créer un dossier
mkdir /srv/storage/cookyst@storage1.lille.grid5000.fr/mon_dossier

# Vérifier l'espace total et libre
df -h /srv/storage/cookyst@storage1.lille.grid5000.fr

# Vérifier les permissions
ls -ld /srv/storage/cookyst@storage1.lille.grid5000.fr
```

---

## 2️⃣ Cas 2 : Nœud sur un autre site (ex : Luxembourg)

* Le storage n'est pas monté automatiquement.
* Il faut utiliser l'API Grid5000 pour autoriser l'accès.
* Endpoint API : `https://api.grid5000.fr/stable/sites/lille/storage/storage1/cookyst/access`

### Étapes :

1. Activer l'accès pour le nœud distant :

```bash
curl -u <login_grid5000> \
     -X POST https://api.grid5000.fr/stable/sites/lille/storage/storage1/cookyst/access
```

2. Une fois l'accès activé, le storage peut être utilisé via autofs :

```bash
cd /srv/storage/cookyst@storage1.lille.grid5000.fr
```

3. Travailler normalement :

```bash
# Lister les fichiers
ls /srv/storage/cookyst@storage1.lille.grid5000.fr

# Créer un dossier
mkdir /srv/storage/cookyst@storage1.lille.grid5000.fr/mon_test

# Vérifier l'espace disponible
df -h /srv/storage/cookyst@storage1.lille.grid5000.fr
```

---

## 3️⃣ Remarques importantes

* Le storage est **PERMANENT**.
* Les fichiers héritent des permissions du groupe `sto-cookyst`.
* Pas de sauvegarde automatique, il est conseillé de faire une copie si nécessaire.
* Sur les nœuds distants, utiliser le **nom exact du storage** : `cookyst` (pas `sto-cookyst`).
